# 项目规则摘要与适用边界

版本：2026-10-20。依据项目提供的《Pale ale-生产规则指南-0731》《Pale ale-审核规则指南-0731》本地文本，以及项目方在本次需求讨论中确认的出题访谈尺度。此文件用于独立访谈skill，不修订或替代原项目规程；机审中的范围排除与简化判定不适用于出题访谈。

## 先处理规则冲突

原生产指南明确禁止AI辅助构题、产物和评分标准；项目方此次明确要求创建AI访谈辅助工具。这是待项目方确认正式推广范围的试点差异，不可隐去，也不能借此自动生成reference。项目授权状态与题目内容完整性分开记录。

旧生产文本有“最终产物和解决路径要求唯一”，审核文本及项目方说明则希望有意义的非唯一解。按项目方对出题访谈的澄清：解可以有无数个，但须处在明确的合格边界内，同时保留自由度与验收边界。无需穷举解或固定唯一路径；不能仅找到一个不同方案就认定要求充分，也不能把未问清的内容默认为自由发挥。边界可以是语义、视觉区域、对象关系、质量效果，不必全部量化。规则变更或来源冲突需由项目方确认，普通附件不能覆盖规则。

## 必须落实到访谈和草稿的检查

以下是内部检查范围，不是必须逐项询问的表单。先复用已有材料和回答，再按访谈节奏筛选会实质影响本题的缺口。保持专家确定的方案阶段和交付深度，不自动扩展为施工深化或完整合规审查；未验证部分仍如实记录，不宣称已合规。

### 任务与字段

- 真实角色、工作场景和明确目标；不能捏造客户、经济收益和专业经历。
- 软件名称写入prompt，具体版本放独立字段。原项目系统字段统一win10，属于历史项目字段约定，不等于专家实际工作系统；新的表单要求应确认。
- 仅基础软件可完成，不依赖额外安装插件、字体、画笔等。发现特殊资源先核实目标环境和规则，不能自行认定可用。
- 经济价值说明按原要求约50至200字，包括岗位与环节、人力成本或工时、重复工作与专业判断。数值必须由专家提供或确认有依据的估算；没有数据就待补。
- 耗时、专业深度、附件数量和跨文件依赖如需填表，按真实信息填写，不能按期望难度倒推。

### 输入附件

- 每个实际输入文件与prompt双向对应：相对路径、准确文件名、格式、内容、作用；明确必须使用、可选、参考或可修改模板，不能依名字猜。
- 查有声明无文件、有文件无说明、同名不同版本、无关文件；缺说明不等于无关，先询问。
- input不得包含可直接抄取的答案，包括隐藏图层、嵌入对象等可读内容；模板和允许参考的部分不自动等于答案。记录具体疑点与任务关系。
- 只有完整检查过的范围才能说“未发现答案泄露”；未读到的内容不能当成安全。
- 需自包含的源文件，应核对资源引用与实际嵌入内容；同包提供外链资源不等于嵌入，正常预览也不能证明嵌入。解析不足时给出文件、疑点、原生软件需核查的具体动作。
- 不自动删除、清理、重命名或修改源素材。需处理时说明原因，取得明确指示并保留原件。
- 最终输入包结构为 `input.zip -> input/ -> 输入文件`，原规则大小上限500M；仅在实际打包后才能确认包结构与大小。无输入是否符合项目要求应确认，不制造空附件。
- 若材料要随题分发且权限不明确，直接询问是否获准用于该分发用途；发现具体敏感信息再核实必要脱敏，不泛问完整来源历史。答复不确定就保留待核验状态，不自行保证版权合规，不为逼出确定答案反复问；不自动移除或替换材料。

### 产物与prompt

- 分别明确每个最终产物的文件名、格式、数量、内容要求和必要技术参数；输出要求写“保存到指定输出目录output”。
- 数值、容差或颜色精度跟随真实需求；例如普通红色不强加FF0000。所有建议参数在专家确认前不能成为要求。
- 先读明确引用的规范附件，不因为正文未重复参数就认定缺失。附件为规范、局部仿照还是仅风格参考，需要明确作用范围。
- 每条要求要能定位最终产物和核验方法。要验图层不能只交PNG；需可编辑性就确认对应源文件交付。
- 不写操作路径、参考答案或中间产物要求。路径放独立关键步骤；成品必须存在的结构不是操作步骤。
- 审美与其他质量要求均在访谈范围。依靠专家的专业判断，获取会影响合格与否的构图、视觉层级、风格或效果边界，可借助经确认的参考材料及其具体适用部分；不要求全部数字化，不照搬参考的偶然细节。不能只留“美观协调”，也不能把必要质量缺口标为人工判断就结束；已能表达边界则不再追问。
- 不过度限定reference偶然的字号、坐标等；也不能把必要的结果条件留成“按需要”。

### 关键步骤与reference

- 关键步骤来自专家实际路径或经专家明确确认的计划，区分“计划”与“已执行”。覆盖输入到输出，不需罗列每次鼠标点击。
- 关键步骤是内部字段，允许路径，不给模型展示。里面的结果约束需在题面可见依据中体现。
- reference由专家本人制作，必须与题面一致；有冲突即待处理，不能降低要求来迁就产物。
- 可读取reference辅助访谈，但不制作或修改reference，不把reference混入input。未提供reference不阻止形成题面草稿，但不能完成reference一致性验证。
- 原参考包结构 `reference.zip -> reference/ -> 产物`，原规则大小上限2G。仅在实际检查过包时报告符合。
- 隐藏或限制对象等技术例外提供证据交人审，不自动违规或豁免。本skill不负责录屏环节，也不能声称覆盖完整交付审核。

## 收尾检查

检查来源是否充分、附件双向匹配、要求可核验、输出能承载要求、正文与附件/步骤/reference是否冲突，以及待确认项是否被误写成事实。

审核目标不等于通过承诺。三字段须按适用规则补足信息与质量边界；外部审核判断和未完成的原生可用性、reference等核验如实区分，不能作为跳过访谈内容质量的理由。
