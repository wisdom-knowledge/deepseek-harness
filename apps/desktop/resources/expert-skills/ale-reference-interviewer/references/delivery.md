# 三字段成稿与停止条件

## 先检查，再展示

内部按下表逐项对照现有文件和专家回答。检查项不是要专家回答的问卷，能够直接完成的自己做。

| 检查 | 达标条件 |
| --- | --- |
| 任务成立与难度 | 当前input到reference的实际工作明确；真实五维评分可排除Easy，且有实质软件操作和专业判断；分数非Easy不自动证明难度够 |
| 必要信息 | prompt原文本身明写任务角色、目标、软件、所有输入用途、产物内容/质量/数量/格式/名称/输出目录；用途或工作情境不替代角色 |
| 边界与自由度 | 不是只写格式和“美观”；关键结果有可核验边界，也未把样本的所有偶然细节锁死 |
| 有据 | 每个硬约束均来自明确适用的材料规范或专家确认，不把观察、推测和专业建议偷换成要求 |
| 一致 | prompt、input、reference和步骤没有未解决的内容/参数/命名矛盾；实际路径与计划不混淆 |
| 文件依赖 | 已知链接、嵌入、答案泄露和缺文件问题已说明并解决；无法读的技术部分单列，未验证不写已验证 |
| 视觉与结构 | 已实际查看可取得的图像，input/reference对应比较；截图事实与结构事实分开，未以预览证明嵌入、编辑性或真实几何 |
| 验收载体 | 每条结果要求可在模型得到的题面/适用input找到依据，并能在要求的最终交付中核验 |
| 不泄题 | reference和关键步骤不在模型可见input；prompt无操作路径和可直接抄用的答案 |
| 经济价值 | 该字段原文本身分别交代执行岗位与环节、数值成本、具体重复工作、具体专业判断，均有依据且匹配本题范围；不能用用途＋工时＋工作名称清单代替四项 |
| 关键步骤 | 专家实际过程已足以支撑输入到输出，顺序合理；没有从文件倒猜后直接称为专家实操 |
| 篇幅 | 三稿无需从聊天捞信息；没有重复说明、访谈回顾、检查结论或无关专业知识 |

明确已存在错误是阻塞；解析工具能力不足是技术未验证，两者不能都写成含糊“建议人工复核”。例如已查到图片外链丢失不能仅附一个提示后称草稿可提交。核心任务内容都读不到时，应请求必要的可读导出，而不是给出虚假的完整稿。

必要信息未齐只输出待补工作稿（若专家要看），清楚注明尚缺项。不能为了三字段齐全而填入猜测的工时、操作路径或约束。已足够即停止，不能为了形式再追一轮。

### 最终原文检查

临展示前逐字段检查实际将输出的文字，而不是检查自己是否读过规则或问过相关问题：prompt中的角色句能直接定位；经济价值中value-and-difficulty.md的四项各有具体文字和依据。正文缺表达但事实已确认就直接补入；事实未知才针对缺项问。不把关键步骤、附件、元信息或另一字段里的内容算作这两个字段已经写全，不期待专家自行补救。专家改稿或要求压缩、改要点/自然段、润色后，重新检查这一点；不为强行凑齐而添加未经确认的事实。

## 按产物收尾，而非围绕最后一个问题收尾

先在内部形成三字段草稿，逐个产物核对下列信息；不向专家展示表格让其填空，不要求每一格都有数值：

| 方面 | 要确认的内容 |
| --- | --- |
| 核心内容 | 专家要交付什么，哪些主体、功能或信息必须存在，哪些只是样本里的可选细节 |
| 关系与边界 | 核心对象的空间、对应、状态或功能关系；允许变化到什么程度，不需要唯一坐标或唯一画法 |
| 结果质量 | 加工后应达到什么状态，例如扩展背景的衔接、装配关系或填写功能；不能只在步骤里出现 |
| 技术与依赖 | 各产物适用的尺寸、单位、色彩、分辨率、编辑对象、依赖完整性；不将整件成品规格无差别套到局部处理稿 |
| 验收依据 | 每条要求在prompt或明确引用的input中可见；reference与该要求相符、已知冲突或技术未验证的状态清楚 |

对每个疑似缺口先问自己：不补它，会不会使一个实质违背已确认目标的结果仍看似合格，或让必要的核验无法进行？能指出具体影响才处理；仅仅不同于原题或reference，不足以要求追问。确认目标本身仍模糊时，请专家说明关键表现或用途，不先替其决定答案。

处理分三路：已有明确依据的遗漏直接补入；必要但意图未知的给出具体问题或少量候选；可选细节保留自由。内部进行少量正常、具有代表性的验收检查，不穷举极端反例。专家确认的新要求与reference矛盾时仍须处理矛盾，不能以“新题可以不同”放行不符合要求的样本。

将回答落实到草稿后，再扫一遍所有产物与三字段：尤其检查口头已答但正文遗漏、结果只写在步骤、观察被升格为要求、成本或步骤因范围变化而失配。所有必要项已有依据或明确合理自由度、没有未解决的成题阻塞时停止；一个分辨率等技术风险解决，不代表其余方面自动齐全。

## 检查发现必须有去向

- 已读取的事实：按每类交付分别检查尺寸/画布、适用色彩或单位、分辨率、内容完整性与源文件关系，不能只规定主产物而漏掉效果图等配套产物。仅将与用途有关的属性提为候选确认，不将reference全部属性自动锁死，也不让专家重新手填可读数值。
- 必要质量边界：结合实际用途确认内容完整、对象形态保持、编辑性和文件依赖等要求。源文件需要换机使用时，明确必要资源的嵌入或随附方式；发现历史路径不等于已经证明缺图。使用过智能对象等操作也不自动等于必须保留该结构的交付要求。
- 实质阻塞：已知缺文件、需求冲突、关键质量不满足或实质难度不足，继续处理；不能用一句待核验、免责声明或缩水用途掩盖。只有专家明确选择新的合理用途，才能变更范围，并联动检查三字段及reference。
- 技术未验证：要求清楚且没有已知矛盾，只因工具不能验证原生结构时，可以形成草稿，但单列具体未验证对象、影响及所需核验，不称reference已合格。核心任务都无法识别时仍需补可读材料。

专家接受某个质量门槛或例外，只证明验收边界达成一致，不证明当前reference已符合。继续核对能够读取的部分；不能验证的保留具体状态。已接受的素材局限通常放在交付外的简短说明中，prompt只保留必要的制作边界，不把访谈诊断过程变成模型新增的报告或印样交付。

例如包装指定印刷用途而素材像素较低，应结合实际放置尺寸检查有效清晰度；导出300dpi不证明素材清晰。若证据不足，问清使用边界或所需高清素材/真实处理工作，不能仅改称“非完整印前交付”后忽略原要求。若只是屏幕展示，则按已确认的展示用途检查，不默认追加印前规范。这是用途与证据的一致性检查，不是所有设计题的固定问卷。

## 输出形式

按prompt、经济价值、关键做题步骤顺序，只展示一套正文。prompt默认紧凑要点，要求提交文案时改为自然段；经济价值默认一段自然文字，关键步骤默认编号。三字段应是专家稍作表达调整即可提交的文本，而非助手向专家解释本题的报告。无需生成meta表、文件盘点或审核报告。

成稿视角是题目提交者，不是访谈记录员。优先直接陈述，不强制第一人称，也不虚构“我在某公司任职”等身份。删除“专家表示”“据专家介绍”“按专家经验”“根据您的回答”等转述；工时和路径的证据来源留在内部，未解决事项留在正文外。经验估计可写“人工通常需要约8～16小时”，不能改成“本次实际耗时8小时”；只有实际记录才写实际耗时。尚未确认的事实不能通过换口吻变成确定事实。

Prompt组织：首句明写任务角色及目标，例如“你是一名平面设计师，请使用……完成……”。要点格式也保留角色，不留给专家自己加。角色取自已明确的任务职责；仅需一般设计职责时用相应通用角色，不编造资深年限、认证或真实任职。后接紧凑的输入文件名、格式、内容和作用；按产物或主题合并结果要求；清晰交付清单及“保存到指定输出目录output”。不要沿访谈问答顺序逐段扩写。

适用input已明确承载的详细参数可以引用，不重复整段。省下的篇幅用于必要的交付质量边界，不把“可编辑文件”“清楚可读”当作对象编辑性、测量可信度、信息定位和文件自包含的通用替代；具体哪些需要约束仍以任务及专家确认为依据。

经济价值：50–200字左右一段即可，信息完整优先于压短；四项具体口径见value-and-difficulty.md。不照搬审核维度逐项自证，不夹带难度评分、访谈来源或泛泛的AI收益。真实人工耗时或费用支持量化，不必两者齐全。例如，在相应事实均已确认时可写：“室内设计师在方案展示和甲方汇报环节，将现有平面线稿处理为彩色方案图，人工通常需1～2个工作日。逐个区域选取、填色和核对边缘属于重复处理；不同区域的材质区分、明暗层次及家具线稿保留需要结合空间关系作设计判断。”示例只说明口吻，不复制其事实到其他题目。不要把“AI将节省90%成本”等未经证实的收益写进去。

关键步骤：通常4–7步，每步一两句，随实际流程调整，不拆动作凑数。用“打开……”“选取……并填充……”“检查……”“保存……”等直接操作句，按已确认的实际流程写清对象、关键处理与必要检查，最后保存交付；不写“专家先……”“模型需要……”“这一步考验了……”或反复说“按要求处理”。保留已确认的关键参数、文件名和判断，不能为了简洁退化为通用操作清单，也不能把访谈没给出的菜单、快捷键或操作路径补成实操事实。仅有计划时标明为拟定流程，不声称它是现有reference的制作凭证。

Prompt能短则短，通常400–800字是编辑参考而非额度；超过1000字先删除叙事、重复和无用细节，再合并要求，不为压字数删除关键关系、准确文件名、单位或必要清单。真实文件清单长时允许超出，不虚构一个新规范附件来压缩文字。

最后用一句话请专家确认或纠正三字段。仅有实质阻塞/技术未验证/授权边界时，另附短提示；不默认输出免责声明长段或宣称审核通过。确认后有修改须联动检查三字段与reference，不只改一处文本。
