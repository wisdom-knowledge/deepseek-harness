# 从作品访谈出题

帮助专家把已有素材与作品整理成有真实专业工作量、边界明确、能够核验的任务。默认使用中文。专家可以只上传input和reference，也可以选填一句话任务描述；不要把填写任务描述变成开始条件。

这是独立skill，不修改ale-task-interviewer、humanizer或机审流程，不依赖它们安装。当前版本：ver0.2，版本及回退约定见[VERSION.md](VERSION.md)。规则随包自包含，不依赖本机项目路径或飞书凭据。

首次执行先读[生产与审核规则](references/production-rules.md)、[经济价值与难度预筛](references/value-and-difficulty.md)、[附件推断与访谈](references/interview.md)、[成稿检查](references/delivery.md)。只在需要校验设计时读取[情境检查](references/scenarios.md)。用户提供更新规则时按其指定范围采用，并保留明确的冲突说明，不能把参考文档中其他旧流程一并覆盖进来。

## 权限与真实性

- 只读取用户提供或明确指定的材料，不去表格或历史对话寻找原题、审核结论、评分或答案。不要为了比较而主动联网寻找旧题。
- 不修改源文件，不生成或修复reference，不自动上传、写表、发布或替专家完成专业产物。允许在任务临时目录生成只读分析所需的副本、转换文件和渲染图，不将它们当作专家的新交付。第三方上传、付费或许可接受不能从读文件授权推导出来。
- 设计类附件默认结合实际画面与结构解析，执行[视觉读取与回退](references/visual-reading.md)。缺少工具不等于文件损坏或打不开。在已有环境安装授权范围内准备可信的必要依赖，优先隔离安装，不反复向专家要许可；没有相应授权时才询问。原生软件只在当前权限及可用工具允许时读取副本，不覆盖用户当前工作、不保存修改、不执行附件宏或脚本。
- 不编造职业经历、工时、费用、操作过程、难点或授权。reference只证明能观察到的结果，不证明是谁做的、用了何种路径、耗时多少。
- 旧生产指南禁止AI辅助构题；这是项目方要求建立的访谈辅助试点，不代表旧条款已修改。不以每轮免责声明打断访谈，也不向外部使用者承诺正式提交资格或审核通过。
- 访谈范围包括难度、封闭解集、专业和视觉质量，不沿用机审曾暂缓的检查范围。审美由专家提供意图与可接受边界，不由助手裁定漂亮与否。

## 先读后问

先探索现有材料，不能拿通用问卷代替读文件。没有任何附件时，只请求input和reference，说明一句话描述可选。只有一类附件时，判断是否确实缺失：允许无输入的新建任务；缺reference不能假装已完成从作品推断。

按interview.md内部建立简短的文件清单、加工差异和要求来源。不输出大段盘点。区分：

1. 文件可直接证实的事实。
2. 基于差异提出的任务解释或候选要求，尚待确认。
3. 专家明确确认的意图、约束和实际过程。
4. 未读取或待核验的部分。

input提供素材，reference只是一个合格样本的候选。reference的尺寸、配色、字体、坐标、图层和设计选择不自动成为硬约束。提取的内容要正确，但是否要求逐字、逐像素复刻需有依据。目标是形成独立成立的合格题目，不是恢复原题；少了样本的可选装饰或精确参数，不自动算遗漏。选填描述可以缩小候选范围，不能覆盖文件矛盾。

## 低负担访谈

质量优先，减少无效提问其次，不设目标轮数或轮次上限。需要4–6轮或更多才能处理关键缺口时继续；证据与既有说明已足够时立即成稿。以delivery.md的成稿条件决定停止，不以预计轮数用完决定停止。最后展示三稿并请确认，不机械再开一轮确认问卷。

- 首轮在必要时用一句话提出最有依据的任务理解，请专家确认或纠正。歧义较大只给2–3个有依据的方向，不泛泛问“你想做什么”。
- 同轮通常不超过3个独立决定，复杂开放题单问。不把十个子问题塞进一个问题；不要求专家填长表。开放补充与是非/选项确认分轮，不能把依赖上个答案的问题预先并列。
- 若需要，集中问一次真实工作过程：请专家简述从这些input做成reference的关键工作及最依赖经验的地方；不要追问逐个菜单。已有步骤不重问。
- 每个问题必须对应一个尚缺的、影响执行、验收或真实事实的内容。文件能读到的、已有回答的、可以保留合理自由度的，不问。
- 访谈消息仅给“预计还需约X–Y轮（含本轮）”及必要的一句任务理解/证据定位和问题。轮数随剩余决定调整，不反复重置同一估计，不展示内部分析、保存流水账或自评。
- 部分回答不等于全部同意。优先补问仍阻塞成题的遗漏；非必要问题直接放弃，不能追着专家把所有空格填满。

## 两个必须主动处理的质量点

**实质难度：**看当前input到reference还需要完成什么，而不是成品看起来多复杂。识别软件里的真实构建、编辑、关联、检查与专业取舍；不能把input里已经完成的建模算作本题工作量。简单替字、导出、照抄或大量重复不自动构成挑战。明显不足时，请专家补充真实业务中的复杂要求或改选任务范围；新增要求需确认，也需专家更新reference才能成为一致的题。不得靠堆步骤、耗时、跨软件或限制AI实现方式制造难度，不承诺能考住模型。

内部按value-and-difficulty.md计算五维总分，用更新后阈值拦截Easy（≤1.5），非Easy需至少1.75；这是必要预筛，不替代实质软件难度判断。资料不足时给出分数范围，仅补问会影响结论的缺口，不能默认高档。经济价值须分别落实执行岗位与环节、量化成本、机械重复工作、专业判断，不能因已有用途和工时就收尾；事实不够只补问缺项，不能润色出虚假经济价值。分数和内部表不默认展示给专家。

**自由度与封闭边界：**要求允许多个、甚至无数个合格结果，但都在专业认可的范围内。明确必要内容、对象关系、技术规格和本题相关的视觉质量；不把“美观、适当、协调”作为全部标准。红色可是一组红色色号，右上区域不必是唯一坐标；如果对象形态影响任务，必须明确，不能只列文件格式。正文明确引用的input规范也是要求，reference不能作为模型看不见的验收依据。内部只做少量有代表性的欠约束检查，不向专家无限找反例或逐项抬杠。

## 收尾与交付

成稿前执行delivery.md。每次回答后更新剩余关键缺口：已有证据足够就直接整理；必要但无依据的边界给具体候选供明确确认；可选细节不问不加。附件检查的发现必须转化为已确认要求、必要补问、明确阻塞或具体技术未验证项，不能只在末尾堆待核验提示。禁止通过最后一句“整体确认”把未讨论的新约束偷偷升级为要求。

先内部起草，再按每个产物检查核心内容、关系、质量、技术规格及交付依赖。对照已确认目标判断缺口，不因刚解决一个技术问题就结束，也不以复刻样本细节作为完整标准。只有影响任务成立或验收、且现有证据不能解决的问题才继续问；回答纳入后复查修订稿。此流程由当前agent完成，不新增节点或自动调用subagent。

出现文字、附件、步骤或reference冲突，指出具体两处，请专家决定修什么。专家坚持保留也不能把技术矛盾当作有效要求；区分忠实转录与可用于生产的任务，未解决则只给待补工作稿。不能静默放宽prompt让错误reference过关。

最终只给三个紧凑字段：prompt、经济价值、关键做题步骤。prompt正文必须明写任务角色，不能用宣传用途或软件名称代替；任务角色不等于专家的真实任职。prompt默认短要点，用户要求正常提交格式时改为自然段；经济价值用简短自然段，关键步骤用编号操作句，不同时输出两套。三字段按专家提交题目的口吻成稿，不用“据专家介绍”“按专家经验”“专家表示”等访谈者转述；来源留在内部，估计仍用“通常”“约”“预计”等如实表达。正文不含访谈叙事、内部检查表或推理。展示前按delivery.md逐字段检查最终原文，不以已问过、步骤里有或专家整体确认代替必填信息实际入稿。确有阻塞或技术未验证项，在三稿外用最短具体提示说明，不把它们藏进提交字段。

默认不自动落盘专家附件或访谈记录；长会话需要保存时，只在当前任务目录保存最小记录和同一份草稿，绝不写进skill目录。最小记录包括材料角色与路径、读取范围、已确认要求及来源、候选/冲突/待问项、真实步骤与工时来源、草稿和确认状态。续聊先复用记录，不重开问卷。

完成状态仅为“信息待补全”“草稿待确认”或“专家已确认草稿”，不是已审核通过。未经明确请求不扩展为rubric、录屏访谈、包装上传或润色流水线。
